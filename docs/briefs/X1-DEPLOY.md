# Brief X1 (Sonnet): paket deploy VPS + runbook untuk Hermes

Basis: main terbaru (repo `projectclientzen/munaja-apps`). Branch `claude/x1-deploy`. Domain dan VPS sudah dipasang owner; detail (domain, OS, Postgres, proxy) BELUM diketahui orchestrator, jadi semua parametrik. Target default: Ubuntu 22.04/24.04, Node 20 LTS, pnpm, PostgreSQL 16 lokal, Caddy (HTTPS otomatis), systemd. Owner hemat kuota: langsung dan fokus.

## Tugas
1. `supabase/stubs/auth_stub.sql` → `supabase/bootstrap/00_roles_auth.sql` (git mv), path di `src/server/db/pglite.ts` disesuaikan. Bootstrap membuat role/skema yang dibutuhkan migration di Postgres polos (tanpa Supabase).
2. `scripts/db-migrate.ts` + script `pnpm db:migrate`: terapkan bootstrap lalu `supabase/migrations/*.sql` berurutan, tabel `schema_migrations(name, sha256, applied_at)`, tolak file yang checksum-nya berubah dan migration baru yang namanya lebih awal dari yang terakhir diterapkan, satu transaksi per file, idempoten. Test `tests/db/migrate-runner.test.ts` (PGlite).
3. `deploy/`: `Caddyfile.example` (domain via env, header keamanan, `X-Forwarded-For`/`X-Forwarded-Proto` ke app), `munaja-web.service` dan `munaja-worker.service` (systemd, user non-root, `EnvironmentFile=/etc/munaja/munaja.env`), `sql/roles.sql` (role aplikasi `munaja_app` dengan hak minimum, tanpa superuser), `backup.sh` (pg_dump harian + retensi 14 hari) + timer systemd, `env.example` (semua env production dari `.env.example`, tanpa nilai rahasia: `DATABASE_URL`, `SESSION_PEPPER`, `PHONE_HASH_KEY`, `MFA_ENC_KEY`, `APP_BASE_URL`, `APP_ORIGINS`, `TRUSTED_PROXY_HOPS=1`, `CRON_SECRET`, `VAPID_*`, `PRAYER_PROVIDER`, `SCALEV_*`, `NEXT_PUBLIC_DATA_MODE=live`), perintah membuat secret acak (`openssl rand -base64 32`).
4. `docs/DEPLOYMENT-VPS.md` = RUNBOOK untuk Hermes/owner, langkah bernomor yang bisa disalin: prasyarat, install paket, buat user + direktori, clone, isi env (secret dibuat DI SERVER, tidak pernah ditempel di chat), `pnpm install --frozen-lockfile && pnpm build`, `pnpm db:migrate`, `pnpm db:regions` bila perlu, start service, cek kesehatan (`curl https://<domain>/api/v1/health` atau endpoint yang ada; buat bila belum ada, tanpa membocorkan info), buat super_admin pertama dengan `scripts/admin-grant-role.ts` (email dari argumen, keluarkan tautan atur password sekali pakai; password tidak pernah di argumen/log), enrol MFA, lalu BAGIAN WEBHOOK SCALEV: URL `https://<domain>/api/v1/webhooks/scalev`, isi `SCALEV_WEBHOOK_SIGNING_SECRET` dan `SCALEV_PAYLOAD_KEY` dan `SCALEV_API_KEY` di env server, restart, BARU simpan webhook di dashboard Scalev (business.test_event harus 2xx), event yang dipilih, cara cek log. Tambah bagian update versi (git pull, install, build, migrate, restart) dan rollback.
5. Smoke lokal: jalankan `pnpm db:migrate` ke Postgres sungguhan bila tersedia di container (apt postgresql), kalau tidak, PGlite + catat bahwa Postgres nyata belum diuji. `pnpm build` harus lolos dengan env production contoh.
