## Keputusan dan temuan
- `service_role` butuh BYPASSRLS, hanya superuser yang bisa membuatnya. Bootstrap saja gagal di Postgres polos dengan role non-superuser ("permission denied to create role"). Solusi: `roles.sql` (dijalankan superuser) membuat `anon`, `authenticated`, `service_role`; bootstrap memakai `if not exists` jadi tetap idempoten. `munaja_owner` bukan superuser dan tanpa CREATEROLE.
- `munaja_app` tidak punya hak langsung. Ia hanya boleh `SET ROLE` ke `authenticated`/`service_role` (cara kerja `src/server/db/pg.ts`). Hak itu diberikan lewat `roles.sql` kedua kali, sesudah migrasi.
- `--seed` memuat `supabase/seed.sql` tanpa blok "DEMO DATA" (wilayah contoh), supaya server nyata tidak membawa wilayah DEMO. Konten (level, aktivitas, setelan) memang wajib ada di production.
- Migrasi dan bootstrap harus dijalankan oleh role yang sama (default privileges di bootstrap berlaku per pembuat objek): `munaja_owner`.
- `admin-grant-role.ts` tidak diubah. `--print-link` menolak output non-terminal, jadi runbook minta sesi SSH interaktif.
- Caddy memblok `/api/internal/*` dari luar (404); endpoint cron untuk curl lokal ke 127.0.0.1:3000.
